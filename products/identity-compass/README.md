# بوصلة الهوية — منصة تقييم وبناء الهوية الشخصية (SaaS)

منتج ويب كامل: تقييم من 140 سؤالاً مبنياً على أبحاث الشخصية والهوية (الخمسة الكبرى، الأنماط الأربعة وستة عشر نمطاً، قيم شوارتز، نقاط القوة، مارسيا، إريكسون، وضوح الذات، الدوافع السلبية، بيئة العمل)، نتيجة فورية مجانية، وتقرير كامل مدفوع بأقسام: الأسس، النمط، السلوك، القوى، التحديات، العلاقات، العمل والمسار، القيم، ما تحرسه، مبدأ الهوية، خطة تسعين يوماً مع تقويم أسبوعي، أسئلة للتأمل، والمراجعة، مع «قراءة الشركة» التي يولّدها Claude كمخرجات منظمة من إجابات العميل.

## التسلسل الذي يمر به العميل

1. **صفحة الهبوط** `/` — القيمة، كيف يعمل، ما في التقرير، العلم وراءه، الأسعار، الأسئلة الشائعة.
2. **التقييم** `/test` — أحد عشر قسماً: الملف السريع (10)، علامات الخلل (9)، وضوح مفهوم الذات (6)، الاستكشاف والالتزام (2)، سمات الشخصية الخمس الكبرى (30)، نمط الشخصية بأبعاده الأربعة (20)، قيم شوارتز (20)، نقاط القوة (24)، الدوافع السلبية (7)، بيئة العمل (6)، وعشر إجابات مفتوحة. 124 بنداً مقيَّماً. الإجابات تُحفظ تلقائياً في المتصفح.
3. **الحفظ** `/save` — بعد آخر سؤال يُطلب البريد (رابط دخول بلا كلمة مرور عبر Supabase)، ثم تُرسل الإجابات وتُحسب النتيجة على الخادم.
4. **النتيجة المجانية** `/results/[id]` — مؤشر وضوح الهوية، النمط بنسبه الأربع، حالة الهوية، مرحلة إريكسون، الخمسة الكبرى، والأقسام المغلقة تظهر مموّهة مع زر الشراء.
5. **الدفع** — Paddle (تاجر السجل: يتكفل بالضريبة والفوترة). الويبهوك يسجل الشراء في `purchases`.
6. **التقرير الكامل** `/report/[id]` — ملف النمط، القوى المميزة، السلوك اليومي، التحديات، العلاقات، العمل والمسار، القيم، ما تحرسه، مبدأ الهوية، تقويم التسعين يوماً (13 أسبوعاً)، أسئلة للتأمل، المراجعة، وزر «اكتب تقريري من إجاباتي» الذي يستدعي Claude بمخرجات منظمة (JSON) ويحفظها في `reports.synthesis`، فتظهر القراءات بدليل والقيم الخمس وثلاث صياغات للرسالة والحدود والمسار وخطة مخصصة تحل محل الخطة القاعدية في التقويم. طباعة أو حفظ PDF من المتصفح.
7. **البناء** `/build/[id]` — الهدف الحقيقي للمنتج: يكتب الشخص هويته بنفسه في سبع خطوات (سطر التعريف، القيم الخمس بتعريف سلوكي، الرسالة بمكوناتها، التموضع والركائز، الهوية الظاهرة، الحدود، الوثيقة) مع اقتراحات على الجانب من نتائجه وقراءة الشركة وزر «استخدم» لكل اقتراح. تُحفظ تلقائياً في `identities` وتخرج وثيقة هوية قابلة للطباعة، قسمها الأول يصلح للنشر.
8. **التطبيق** `/plan/[id]` — متابعة التسعين يوماً أسبوعاً بأسبوع: العادات الثلاث، المعالم، تأمل أسبوعي بسؤال من تقريره، ونسبة التزام. تُحفظ في `plan_progress`.
9. **الحساب** `/account` — التقييمات السابقة مع روابط التقرير والهوية والخطة.

## البنية

```
src/lib/engine/        محرك التقييم (بلا أي اعتماد على الإطار)
  items.ts             بنك الأسئلة: 124 بنداً مقيَّماً + 20 بنداً وصفياً/مفتوحاً، كلها بصياغة أصلية
  types16.ts           ملفات الأنماط الستة عشر، نقاط القوة الاثنتا عشرة، بنود بيئة العمل
  scoring.ts           الحساب: العلامات، الوضوح، مارسيا، إريكسون، الخمسة الكبرى، النمط (مع فحص الاتساق مع السمات)، القوى، بيئة العمل، شوارتز (تمركز نسبي)، الدوافع، المؤشر المركّب
  report.ts            التقرير القاعدي: 18 كتلة بحسب النتائج والنمط + مبدأ الهوية + buildPlan (عادات وتجارب ومعالم وإيقاع أسبوعي)
  synthesis.ts         توجيه Claude لقراءة الشركة (بيانات فقط، كل قراءة بدليل)؛ synthesis-schema.ts مخطط zod للمخرجات المنظمة
  identity.ts          وثيقة الهوية: المسودة من النتائج، الاقتراحات لكل خطوة، النص القابل للطباعة، وتقدم الخطة
  scoring.test.ts      اختبارات Vitest
src/app/               صفحات Next.js (App Router) ومسارات API
src/components/        المعالج، النتائج، الدفع، السرد
src/lib/supabase/      عملاء Supabase (متصفح، خادم، service role)
supabase/migrations/   مخطط قاعدة البيانات وسياسات أمن الصفوف
```

## التشغيل محلياً

```bash
cd products/identity-compass
npm install
cp .env.example .env.local   # واملأ المتغيرات
npm run dev                  # http://localhost:3000
npm test                     # اختبارات المحرك
```

بلا متغيرات Supabase يعمل الموقع في **وضع محلي**: التقييم يُحسب في المتصفح وتظهر النتيجة المجانية في `/results/local` دون حفظ.

## الإعداد الكامل (ساعة واحدة تقريباً)

### 1. Supabase (المصادقة وقاعدة البيانات)
1. أنشئ مشروعاً على supabase.com.
2. شغّل ملفات `supabase/migrations/` بالترتيب (0001، 0002، 0003) في SQL Editor.
3. Authentication → Providers → Email: فعّل «Magic Link». Authentication → URL Configuration: أضف `https://your-domain/auth/callback` إلى Redirect URLs.
4. انسخ `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` إلى `.env.local`.

### 2. Claude (السرد الشخصي)
- مفتاح من console.anthropic.com في `ANTHROPIC_API_KEY`. النموذج الافتراضي `claude-opus-5` (متغير `CLAUDE_MODEL`).
- الطلب يستخدم التفكير التكيفي والمخرجات المنظمة (`client.beta.messages.parse` مع مخطط zod)، مع `fallbacks: "default"` لإكمال الطلب تلقائياً على نموذج بديل إن رُفض.
- التكلفة التقريبية للقراءة الواحدة نحو دولار (نحو 3 آلاف رمز مدخل و4 آلاف مخرج مع التفكير)، وتُولّد مرة واحدة لكل تقييم وتُحفظ.
- مدة الطلب دقيقة إلى ثلاث؛ على Vercel اضبط `maxDuration` (موجود في المسار) وخطة تسمح بذلك.

### 3. Paddle (الدفع)
1. حساب Paddle (Sandbox أولاً). أنشئ منتجاً «التقرير الكامل» وسعراً لمرة واحدة، وانسخ `pri_...` إلى `NEXT_PUBLIC_PADDLE_PRICE_REPORT`.
2. Developer Tools → Authentication: مفتاح API (`PADDLE_API_KEY`) ورمز العميل (`NEXT_PUBLIC_PADDLE_CLIENT_TOKEN`).
3. Developer Tools → Notifications: وجهة جديدة إلى `https://your-domain/api/webhooks/paddle` مع حدث `transaction.completed`، وانسخ السر إلى `PADDLE_WEBHOOK_SECRET`.
4. للتجربة بلا دفع: `FREE_MODE=true` يفتح التقرير الكامل للجميع (لا تستخدمه في الإنتاج).

بديل محلي: أي بوابة سعودية (Moyasar، Tap) تُضاف بمسار ويبهوك مماثل يكتب صفاً في `purchases`؛ صفحة التقرير لا تعرف مزود الدفع.

### 4. النشر
- Vercel: استورد المستودع، Root Directory = `products/identity-compass`، أضف المتغيرات نفسها، وحدّث `NEXT_PUBLIC_SITE_URL`.
- أعد ضبط عناوين Supabase وPaddle على النطاق النهائي.

## نموذج العمل المقترح

| المستوى | السعر | يشمل |
|---|---|---|
| النتيجة الأولى | مجاناً | ستة مؤشرات تخبر العميل أين هو |
| التقرير الكامل | 49 ر.س لمرة واحدة | التقرير الكامل، قراءة الشركة، مرحلة البناء ووثيقة الهوية، متابعة التسعين يوماً، PDF |
| بلس (لاحقاً) | 19 ر.س شهرياً | إعادة التقييم كل 6 أشهر، أداة رسالة العشرة أشخاص، متابعة الخطة |

الأسعار للعرض فقط؛ السعر الفعلي يُضبط في Paddle. الحد الأدنى القابل للبيع الآن هو المستويان الأولان.

## ملاحظات قانونية وعلمية

- التقييم **تطويري لا علاجي**؛ الصفحات تقول ذلك صراحة ولا تستخدم مصطلحات إكلينيكية.
- كل العبارات أصلية. المفاهيم المقاسة علمية منشورة (Big Five، Schwartz، Marcia، Erikson، Self-Concept Clarity) لكن لا نستخدم بنود مقاييس محمية.
- النسب تعبّر عن موقع العميل على المقياس لا عن مقارنة بعينة سكانية؛ بعد جمع عدد كافٍ من الإجابات يمكن إضافة معايير سعودية حقيقية (percentiles).
- بيانات العملاء خاضعة لنظام حماية البيانات الشخصية السعودي: احذف بطلب العميل، ولا تشارك مع أطراف تسويقية.

## هل الذكاء الاصطناعي ضروري؟

الحساب والتقرير القاعدي بلا ذكاء اصطناعي: ثابتان ورخيصان ويعملان دون مفاتيح. الذكاء الاصطناعي يضيف الطبقة التي تجعل التقرير يشبه عمل شركة هوية: يكتشف النمط الذي يتكرر عبر مصادر مختلفة (ما يقوله الناس، القرارات الفعلية، الدوافع، السمات) ويربط كل قراءة بدليل، ويخصص الخطة. لذلك التصميم هجين: المحرك يقرر الأرقام، وClaude يقرأها بشروط صارمة (بيانات فقط، حقل `missing` لما ينقص، مخطط JSON ثابت).

## ما يلي بعد الإطلاق

1. جمع 200 إجابة ثم مراجعة اتساق البنود (ألفا كرونباخ لكل سمة) وتعديل الصياغات الضعيفة.
2. معايير محلية للنسب المئوية.
3. أداة «رسالة العشرة أشخاص» (روابط تغذية راجعة مجهولة تُجمع في التقرير).
4. لوحة إدارة بسيطة: المبيعات، معدل التحويل من النتيجة المجانية إلى التقرير، وقت إكمال التقييم.
